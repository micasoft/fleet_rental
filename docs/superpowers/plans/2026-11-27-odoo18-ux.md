# Odoo 18 UX refresh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Odoo 18 markup and a better UX for every screen, report and email; a mobile-first pickup screen, a new drop-off screen, and "Complete pickup / drop-off" actions.

**Architecture:** Additive model changes only (drop-off odometer/photos/signature, two actions). Everything else is XML (views, reports, mail templates) rewritten in place, keeping record xml ids so existing databases update cleanly. Tests load every view through `get_views`/`Form` and pin the new behaviour.

**Tech Stack:** Odoo 18 (Python 3, QWeb, OWL views), tests via `make test` (docker, throwaway DB).

**Spec:** `docs/superpowers/specs/2026-11-27-odoo18-ux-design.md`

## Global Constraints

- No technical field renames, no field type changes, no migration script. `string=` labels may change.
- Keep existing xml ids of views, actions, menus, reports and templates (so `-u` replaces them instead of duplicating).
- `PICKUP_FIELDS` stays the server-side authority for what a Pickup/Dropoff user may write.
- No `<tree>`, no `attrs`/`states`, no `colors=`, no inline `style` on views; v18 settings markup (`<app>/<block>/<setting>`), kanban `t-name="card"`.
- Never touch `.env` or `.secrets/`.
- Work on branch `odoo18-ux` (never on master); commit per task; no push unless the user asks. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, no Claude-Session trailer.
- Do not bump `__manifest__.py`: `make release BUMP=minor` produces 18.0.2.1.0.
- `make test-check` must stay green (98 tests today, plus the new ones).

## Review Focus

1. A pickup user completing a pickup on a contract handled by someone else (rule says they can't see it) must get an access error, not a state change via `sudo()`.
2. Completing a drop-off whose km is lower than the pickup km (typo on the phone) must be refused with a clear message.
3. A pickup user opening the back-office contract form/actions must not get a crash from fields they can't read (`groups=` on totals).
4. Existing databases: `-u fleet_rental` on a DB with the 18.0.2.0.0 views must succeed (inherited views by other modules referencing removed nodes — none known, but `button_box`, `oe_title` names kept).
5. The phone form must not demand a field the pickup user cannot write (e.g. required non-pickup fields shown editable).

Each is pinned by a test in the task that owns it (1, 2 → Task 2; 3, 5 → Task 3/4 view tests; 4 → the update run in Task 7).

- Produces: `action_complete_pickup(self) -> bool`, `action_complete_dropoff(self) -> bool`.
